# 失物招领图片

## 使用方式

进入小程序「失物招领 → 发布寻物 / 招领」，填写标题和描述，在「物品图片」中拍照或从相册选择图片。

- 图片可选，最多 6 张，每张不超过 5MB，支持 JPG / PNG。
- 点击缩略图预览，点击右上角关闭图标移除。
- 点击「提交发布」后逐张上传，按钮显示进度；失败后保留文字、图片和已上传的图片编号，再次提交会复用成功的上传。
- 上传过程中离开发布页，会停止后续提交；已经发出的发布请求仍可能成功。
- 发布后进入审核，管理员可在审核列表查看缩略图和大图。审核通过后，广场展示封面和图片数量；点击信息进入详情，再点击图片查看大图。
- 待审核或下架图片仅发布者、管理员及审核员可读取。

## 接口与存储

`POST /api/v1/lost-found/images`：登录后使用 multipart 字段 `file` 上传一张图片，返回 `id`、`url`、`width`、`height`。

`POST /api/v1/lost-found`：原字段之外可传入 `imageIds` 数组。数组顺序决定图片展示顺序；只能引用当前用户上传且尚未绑定其他发布的图片。省略数组时兼容原有纯文字发布。

`GET /api/v1/lost-found/images/{id}`：返回图片。公开图片可游客读取，其他图片需在请求头携带当前用户 Bearer token。小程序通过 `wx.downloadFile` 获取临时文件后展示与预览。

数据库迁移为 `V3__lost_found_images.sql`，新增图片记录表；保留原 `lost_found.images` JSON 字段及旧接口格式。服务端验证实际像素格式、大小、尺寸，并重新编码去除 EXIF，不采用上传文件名。

图片默认保存在项目工作目录的 `data/lost-found-images/`，可通过环境变量 `LOST_FOUND_UPLOAD_DIR` 指向持久目录。部署、备份时同时保存数据库和该图片目录；多实例部署需使用共同的存储目录。本版本尚未定期清理未绑定发布的上传图片。

正式微信环境应将服务端 HTTPS 域名加入 `request`、`uploadFile` 和 `downloadFile` 合法域名。本地模拟器使用现有本地服务配置；真机需能访问后端地址。
