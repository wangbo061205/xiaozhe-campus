# 校园地图与实时出发

## 当前交互

1. 打开地图先看到校园全览和地点列表，可用搜索、推荐地点或全部分类选择目的地。
2. 选中地点后自动获取当前位置。起点固定为“我的当前位置”，不需要手选地点或路线模式。
3. 点击唯一导航按钮“出发”后，请求校园步行路线；视野同时容纳校园边界和完整路线。
4. 地图前台可见期间，从微信持续定位流每 5 秒取最新位置。位置移动超过约 3 米时重算路线；站立不动保留位置，避免重复路网请求。
5. 离开地图、关闭目的地或切换校区时停止定位；回到已有导航页面时恢复。定位仅前台运行，不开启后台定位。

## 加载恢复

已核实的 3 个校区、10 个分类和 133 个公开地点随小程序保存，并在连接成功后更新本地缓存。启动先显示校园与地点，再同步网络内容，不等待排行、校准和室内概况全部返回。请求最多等待 8 秒，附加信息失败不阻止地点列表显示。

接口不可用时可继续浏览、分类、搜索已保存地点，并明确显示“已保存的校园地点”和重新连接入口。地图底图瓦片和新的校园道路规划仍需要网络；不伪造道路或把直线当成步行路线。

## 定位与权限

`app.json` 声明 `getLocation`、`startLocationUpdate`、`onLocationChange`。首次进入地图不弹定位请求，选目的地或点击定位图标后才申请。拒绝权限或定位失败有页面提示，点击定位图标可重试或打开微信位置设置。

只将校园公开信息写入地图缓存。用户的实时坐标仅保存在当前页面内存，用于路线请求；不写入本地校园数据文件或缓存。

## 验证

- Node 测试覆盖 5 秒采样、停止后迟到回调、拒绝权限/超时、静止状态与位置错误、当前起点更新、目的地切换与请求竞态、坐标校准及到达状态。
- 微信地图 WXML / WXSS 编译通过，真实校区地点列表及目的地单按钮布局已检查。
- 真实上游路网验证：17 号楼到法学院返回 33 个路线点、268 米、约 3 分钟。模拟器以 17 号楼测试起点验证路线界面，未伪造路线数据；测试后恢复真实定位。
- 上游仍有未连通道路，例如西校区东门到合苑餐厅的已测请求。此类失败会清除旧路线并说明原因，需路网维护方补齐道路，前端不能将其宣称为导航成功。
