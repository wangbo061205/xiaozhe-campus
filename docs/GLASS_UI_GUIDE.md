# 液态玻璃交互效果：沟通指南

这份文档是独立的说明，不属于 `BUILD_PLAN.md` 的步骤。它回答一个问题：**想要 iOS 27 那种液态玻璃的质感和交互，该怎么向 Claude（聊天）和 Claude Code 描述，才能一次比一次更接近？**

基础视觉规范（颜色、玻璃层级、动效时长）见 `docs/SPEC.md` §10，本文只讲"怎么沟通和调整"。

---

## 1. 先认清现实：三端能做到的程度不同

| 效果 | 网页 | 小程序 | Android |
|---|---|---|---|
| 半透明 + 背景模糊 | 可以 | 可以（`backdrop-filter`，低端机要降级） | Android 12+ 完整，更低版本降级为半透明纯色 |
| 边缘高光、渐变描边 | 可以 | 可以 | 可以 |
| 弹性、水滴般的形变动效 | 可以 | 可以，但要用 worklet 动画或 CSS，避免高频 `setData` | 可以 |
| 透过玻璃的真实"折射" | 通常只有部分浏览器支持，需要实测 | 基本做不到，只能用高光和模糊近似 | 需要较新系统和着色器，Claude Code 要先查当前文档 |

结论：**三端先统一做到"模糊 + 高光 + 弹性动效"**，折射作为网页端和 Android 的后续增强，做不到的地方明确降级，不追求像素级一致。

iOS 27 的具体新细节，以你提供的参考图为准，Claude 不一定完全了解最新版本。

---

## 2. 怎么给参考

- **优先截图，不要只用文字。** 每个要调的元素至少给：静止、按下、拖动中、松手后四张关键帧。
- Claude 看不了视频：录屏请截关键帧，再用一句话补充动效（"从左滑到右，中途变长，到位后回弹一点"）。
- 放进项目的 `docs/ref/`，文件名带元素和状态，例如 `tabbar-idle.png`、`tabbar-press.png`、`sheet-half.png`、`sheet-drag.png`。
- 也可以直接把截图拖进对话。对话里发的图，Claude Code 看不到，需要重新放进 `docs/ref/` 或拖进 Claude Code 的对话。

---

## 3. 描述句式

**【哪个元素】在【什么操作】时，【怎样变化】，像【iOS 里哪个地方】。**

好例子：
- "底部标签栏点击时，选中的玻璃块像水滴一样滑到新标签，滑动中轻微拉伸，到位后回弹一点，像 iOS 的标签栏。"
- "地图底部抽屉向上拖时，背景模糊从弱变强；松手后按速度吸附到最近的一档，带橡皮筋阻尼，像 iOS 地图。"
- "聊天输入坞获得焦点时，整体轻微上浮、边缘高光变亮，长文字时高度弹性增长。"

不好的例子：
- "更高级一点""更丝滑""更像苹果"。这些没有方向，没法落成参数。

## 4. 可调参数词汇表

你用左列的词，Claude 和 Claude Code 就知道改右列的东西。

| 你说 | 对应调整 | 常见方向 |
|---|---|---|
| 更通透 / 更雾 | 背景模糊半径、底色透明度 | 通透：透明度降低、模糊适中；雾：透明度升高、模糊加大 |
| 边缘更亮 / 更有立体感 | 描边高光透明度、顶部高光渐变 | 顶部比底部更亮，细描边 1px |
| 更圆 / 更方 | 圆角 | 卡片 24、浮层 28~32、胶囊取半高 |
| 更悬浮 / 更贴地 | 阴影模糊与偏移、透明度 | 悬浮：大模糊、低透明度的阴影 |
| 更弹 / 太弹了 | 弹簧回弹幅度与次数 | 回弹减半、只回弹一次 |
| 更快 / 更慢 | 动画时长 | 按压 180ms、切换 320ms、抽屉 480ms 为起点 |
| 更跟手 / 更滑 | 拖动阻尼、速度吸附阈值 | 跟手：阻尼小；滑：吸附阈值低 |
| 按下去更明显 | 按压缩放比例、高光变化 | 0.97 起，可到 0.94 |
| 更有水的感觉 | 形变时的拉伸比例、饱和度 | 拉伸幅度小而快，背景色透过时饱和度略升 |
| 文字看不清 | 玻璃底色不透明度、文字颜色 | 对比度 ≥ 4.5:1 优先于通透 |

每次只改 1~2 个参数，改完看效果再决定下一步。

## 5. 一次只调一个元素：玻璃实验页流程

1. 让 Claude Code 在各端做一个仅用于调效果的"玻璃实验页"（开发期才有，上线前删除或隐藏），把卡片、按钮、标签栏、抽屉、输入坞、对话气泡分开摆放，各占一块。
2. 从最重要的两个开始：**聊天输入坞**和**地图底部抽屉**。每个调到满意再换下一个。
3. 满意后，把最终参数写进第 9 节的记录表，再让 Claude Code 把这个元素套用到真实页面。
4. 三端对齐：先在小程序（第一个交付的端）定稿，再让另外两端对齐，逐端说明差异。

## 7. 怎么验证效果

- **网页端**：让 Claude Code 用 Playwright 在不同状态下截图，对照参考图自查，再发给你确认。
- **小程序**：Claude Code 无法操作微信开发者工具，需要你在开发者工具或手机预览里截图，放进 `docs/ref/` 或拖进对话。**一定要在真机上看**，模拟器的模糊和动效与真机有差别。
- **Android**：用模拟器或真机截图，最好同时测一台较旧的机型。
- **卡顿时先告诉我们手机型号。** 常见处理：减少同屏模糊层、缩小模糊区域、改用静态背景、关闭低端机上的折射。

性能底线（来自 `SPEC.md`）：同屏可见的模糊层不超过 2 层；动画只用 `transform` 和 `opacity`；尊重系统"减少动态效果"设置。

## 8. 给 Claude Code 的规则

以下规则适用于所有玻璃效果相关的修改：

1. **只改被点名的元素**，不要顺手改其他地方的样式。
2. 玻璃参数集中放在各端的 tokens 文件里（Phase 3.2、5.1、10.2 创建的那个），不要在组件里写死数值。
3. 每次修改后说明：改了哪个参数、旧值 → 新值，让用户能对比。
4. 不确定 iOS 的真实表现时，**向用户要参考图，不要猜**。
5. 某个平台实现不了时，明确说明，并给出降级方案和对应效果差异，不要悄悄省略。
6. 修改前先查当前平台文档（微信 `backdrop-filter`、Compose 模糊与着色器相关 API 等），不要凭记忆写参数。
7. 低端机或系统版本不足时必须有降级路径：不支持模糊时用不透明底色，不支持折射时用高光近似。
8. 满足无障碍：文字对比度、减少动态效果、键盘焦点可见（网页）。
